# Curated Commons entity avatars and clustered, touch-sized SVG map markers

The branch adds 11 self-hosted 160px entity avatars (refs #83): exact Wikimedia Commons titles in `config/media_entities.json`, a Commons `imageinfo` lookup in `src/media.py`, a licence regex narrowed to public domain, CC0, CC BY and CC BY-SA, and a manifest with credit, licence, licence URL and SHA-256 of the original. It also adds greedy marker clustering, 44px hit circles on phones and a tap-opens-drawer handler on the self-hosted SVG map (refs #44). No third-party tiles or runtime requests were introduced, and the 28 tests in `tests/test_media.py` and `tests/test_map_clustering.py` pass. The licence gate does what #83 asks. The map interaction has accessibility gaps, and the avatars do not appear until `docs/data.json` is regenerated.

Watch for: (1) the SVG is `role="img"`, so its new button markers are likely hidden from screen readers (likely); (2) clustering does not guarantee non-overlapping hit areas (confirmed); (3) the Giants logo is Commons "Public domain" but flagged `trademarked`, and the other four company logos need the same trademark note (confirmed for Giants); (4) the map tests are mostly string greps, with no test for the tap, keyboard or cluster-list behaviour (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

Entity images are curated, not searched. Each entity maps to one exact Commons file title. Staging reads licence and author from Commons `extmetadata`, drops files whose licence does not match the allowlist regex, checks the downloaded bytes against the Commons sha1, and records the SHA-256 of the original. SVG logos are rendered from Commons' 320px PNG thumbnail while the manifest records the SVG original. Approval and the manifest remain a manual step. Logos are public domain as copyright but still trademarks, and nothing in the UI says so.

The export pipeline already carries `entity_image_path`/`entity_image_credit` and the drawer already renders a same-origin avatar with a visible credit. The branch does not refresh `docs/data.json`, so no avatar is visible on the live page after merge. `WORKING_NOTES.md` states this openly. The tests do not catch it, because the export-path test only checks files that exist in `data.json`.

The map keeps the self-hosted SVG, which satisfies the #82 constraint of no third-party tiles. Pins within a hit-diameter of each other merge into a numbered cluster. A single pin opens the record drawer on tap or Enter/Space. A cluster opens a list in the selected-card region. The mechanics work, but the accessibility semantics and the clustering invariant are weaker than the PR claims. Tests lean on source-string matching.

## Accessibility of the new marker interaction

The SVG root keeps `role="img" aria-label="San Francisco commitment coordinates map"` (`docs/app.js:1497`). Under ARIA, `img` has presentational children, so the markers added or kept here (`tabindex="0" role="button"` with per-marker `aria-label`s, including the new cluster label "N commitments in this area. Select to list them.") are likely not exposed by assistive tech, although they stay tabbable. The label work in the diff is wasted until the SVG role changes. The role itself predates the branch, but the branch builds the touch and keyboard interaction on it.

A cluster activation renders the list into `#map-selected-card` and sets `aria-live="polite"` (`docs/app.js:1544`). Focus stays on the cluster, and `scrollIntoView({block:'nearest'})` is the only movement. On phones the card sits below the map, so a keyboard or switch user gets no visible focus change.

A single-pin activation now both fills the selected-card with the old summary and opens the drawer (`docs/app.js:1517-1533`). The card's "Inspect full commitment" button therefore duplicates what already happened.

## Greedy clustering and touch-target sizing

`clusterPins` sorts by `promise_id`, assigns each pin to the first cluster within `minDist` of its current centroid, then recomputes the centroid. Two things follow. A pin can end up farther than `minDist` from the final centroid of the cluster it joined, and two clusters can end up closer than `minDist` after centroids shift. Hit circles, whose diameter is `minDist`, can overlap, which defeats the point of the 44px target. The test (`tests/test_map_clustering.py`) only asserts that the pin count is preserved and the cluster count does not exceed the pin count, so it passes regardless.

The scale is read from `mapWrap.clientWidth` at render time and falls back to 1 if the map is hidden. The resize handler only re-renders for width changes over 40px, so a change in `(pointer: coarse)` without a width change keeps stale target sizes. `lastMapMobile` is dead.

## Licence gate and Commons staging

`OPEN_LICENSE` at `src/media.py:45` accepts `public domain`, `pd`, `cc0` and `cc by[-sa] <digit>`, and rejects `CC BY-NC`, `CC BY-ND`, `CC BY-NC-SA` and "Copyrighted free use" (tested). Gate checks occur at staging (`commons_file_info`, licence from Commons metadata) and at apply (`check_approved`, line 332) on the human-entered `license`. The apply check does not compare that value with `suggested_license`, so an approver can type a different compliant-looking licence over a NC one. Possible; verify whether a review step catches it. The hash recorded for SVG avatars is the original's, while the avatar bytes come from the thumbnail (`src/media.py:397-401`); the thumbnail content is not hash-pinned.

Spot checks against the live Commons API on 2026-11-23: Lurie and Preston are "Public domain" with sf.gov / sfbos.org sources (government works, plausible; credit for Lurie names the subject rather than a photographer). The Giants logo is "Public domain" with `Restrictions: trademarked`. `WORKING_NOTES.md` acknowledges trademark status, but the manifest, UI and credit string do not.

Credit is rendered as `credit / license` in 0.6rem monospace and never links to `license_url` or the Commons source page. The licence URL and `original_url` stay in the manifest. Zero third-party requests at load is satisfied: avatars use `media/entities/...` relative paths, and `entityAvatarHtml` (existing code) rejects schemes, leading slashes and `..`. `original_url` values are metadata, never fetched by the page.

## Test adequacy

`tests/test_media.py` covers the regex, a mocked Commons flow (sha1 mismatch, empty licence and NC are skipped, UTM query dropped, User-Agent set, SVG thumb render with original hash) and a manifest consistency check (file exists, 160x160, licence matches the gate, config and data names). Not tested: that every manifest entity is exported in `docs/data.json`; the apply-time `suggested_license` mismatch; thumbnail integrity. `tests/test_map_clustering.py` runs the pure block in node, but the interaction tests are source greps. Not tested: tap, keyboard, cluster list, resize re-cluster, focus. The real-export test copies projection constants from `app.js`, so a projection change would silently diverge.
